# Independent local lab summaries

This ledger is a review artifact. It does not update the served atlas or the collection workspace.

- `manifest.json`: complete 868-ID baseline plus explicitly accepted additions from completed exports or the separately audited, frozen reviewed incremental handoff.
- `packets/<labId>.json`: captured official source text, title/headings, original observation times, content dates if advertised, hashes and read-only cache reference. IDs for sources are deterministic. Refreshes retain sources cited by existing records.
- `records/<labId>.json`: individually reviewed, model-authored Chinese synthesis. Each record is atomically replaced and can resume independently.
- `summaries.jsonl`: validated summary projection, including exact supporting source text and uncertainty.
- `url-verification.jsonl`: transport result, final destination, advertised canonical link, redirect chain, robots/access failure, destination identity, separate entity identity, and source-reported affiliation.
- `queue.json`: exhaustive accounting, including genuinely unprocessed records. A missing record never becomes a failure.
- `checkpoint.json`: counts and validation errors, replaced after the two JSONL projections.
- `followups.json`: explicit research, identity, access and historical-check follow-ups. A follow-up is never counted as a new live verification.
- `REVIEW.md`: readable projection of all reviewed Chinese summaries, types, evidence links and capture/review dates.
- `gap-plan.json`: reviewed identity followups and explicit same-site research/about links. Fresh captures are reused; genuine uncaptured public gaps use the verified shared coordinator. `gap-results.json` and `gap-cache/` exist only after permitted requests.
- `network-coordination.json`: explicit readiness receipt. It records the actual live collector PID, all seven loaded dependency hashes, exact own-worktree source snapshots, and offline adapter tests. Every robots request, redirect and page transport uses the shared gate. There is no global wait for the Profiles queue.
- `reviewed-incremental-import-receipt.json`: the frozen 16-ID handoff/decision hashes, verified raw source hashes and original times, explicit acceptance bindings, ignored aliases/updates, and unfinished collection snapshot. Historical import receipts preserve the12-ID and14-ID batches; `HANDOFF-16-DELTA-REVIEW.json` reviews the latest two additions.
- `local-validation-tests.json`: the passing summary/content/network/import tests and exact code/test hashes.

`supported` means an entity match and source-supported research description. It does not imply all methods, current employment, funding, openings, or continued operation are verified. `partial` means identity or limited material was reviewed but a sufficient research description was not captured. `awaiting_collection` means a concrete needed capture is pending. `unresolved` preserves a specific access, identity, or source gap after individual review. Empty arrays mean no explicit supported statement captured.

`lastCheckedAt` is the actual destination-check time, if known. `observedAt` is the original evidence-capture time. `reviewedAt` is the actual synthesis time. These dates are intentionally separate. An undated source remains undated. A known content date is preserved without claiming that the complete page has that date.

`checkOrigin` and `liveCheckedByThisTask` distinguish collection-cache reuse, preserved historical URL checks, and a live request actually made by this summary task. `liveCheckedAt` records an actual page wire start; robots-only checks leave it empty. `followupChecks` describes separate research/identity URLs without replacing the listed destination. `captureOrigin` applies the same distinction to each evidence excerpt. Cache reading is not a fresh live verification. The setup receipt confirms this chat's configured model as `gpt-6.1-sol` and formal Goal as active.

`canonicalUrl` uses the observed final destination only, as stated by `canonicalBasis`; `canonicalLinkUrls` separately records the site's advertised canonical URL. Neither confirms identity. `pageIdentity` requires evidence from the destination; historical directory identity is retained separately as `entityIdentity`. HTTP 200, redirects to login, unavailable robots, DNS, timeout and HTTP errors are not equivalent results. A failed visit does not prove an entity has closed.

`listedUrl` preserves the original baseline/handoff URL. `checkedUrl` identifies the evaluated fetch target; `requestedUrl` identifies the original page request only when `pageRequestProven` is true and is null for robots-only access checks. `checkScope` distinguishes direct or related page requests from their access prechecks. Request matching preserves HTTP/HTTPS, `www`, and non-root trailing-slash differences. Only literal request encoding, such as parentheses versus their percent-encoded wire form, is normalized. A matching original-URL capture takes precedence over a newer arrival through a different URL. If only a related address was captured, its final URL, redirect chain, time and page identity remain visible, but it cannot count as a verified original listed URL. `lastCheckedUrl`/`lastCheckScope` apply the same distinction to summaries. This corrects the earlier545-count milestone:48 previously counted successes had only related-address proof.

Evidence source objects keep `queueUrl` separately from the actual `requestedUrl`/`checkedUrl`; follow-up checks keep their original `discoveryUrl`. A discovery or normalization step is never an HTTP redirect. Destination identity quotes must match the selected capture's actual request URL, body hash, original observation time and final URL. The saved-output audit checks both projections against packet provenance and literal source excerpts, including checks for invented redirects or post-write evidence changes. `REQUEST-PROVENANCE-IMPACT.json` and `REQUEST-PROVENANCE-QA.md` document the correction and independent audit. No new requests were made to inflate direct-check counts.

Page-request proof uses a top-level page HTTP result (including an attempted transport failure), an actual initial HTTP redirect, or explicit wire evidence. A robots HTTP200 alone proves no page request. A real initial page redirect followed by blocked destination robots remains an attempted initial page request. Cache reuse retains the original capture proof and date while `liveCheckedByThisTask` stays false. `request-scope-metadata-refresh.json` records the metadata-only scope refresh: no HTML reread, original-source change, timestamp substitution or network request. URI-target matches and actual page-request counts are deliberately distinct.

No network access is performed by `scripts/local_lab_summaries.py`. It reads the collector's queue, captures and authorized exports without modifying them. The separate incremental importer pins the audited handoff and decision hashes, verifies its frozen stable IDs and source manifest, and appends only labs. Aliases, updates and faculty changes are ignored. `reviewed_incremental` remains non-final while global collection is pending. Unreviewed discovery candidates are never eligible additions.

`approved-handoff-snapshots/` preserves the exact already-approved handoff and decisions bytes. The importer prefers these immutable pinned copies; a changed mutable collector handoff is telemetry only and cannot admit new IDs. `HANDOFF-REVISION-AUDIT.md` documents the first regenerated revision: only three queue/generation headers changed, while all12 lab objects,17 source captures and68 literal field proofs matched. Future semantic additions still require separate explicit review and pins.

The later14-ID pins add only Healthcare Robotics Lab and MILPAS Lab after an independent delta audit. `prepare --append-reviewed` retains all existing packet bytes, dates and ordinal order and prepares only newly admitted IDs. Existing scientific records keep their earlier approved provenance. This14-ID historical milestone preceded the separately reviewed16-ID batch. `REVIEWED-14-NEW-LAB-SUMMARIES.json` records separate Chinese research synthesis; collection acceptance alone never supplies research support.

Live follow-up requires the active cross-process `fcntl-host-clock-v2` protocol, exact loaded-source hashes, an actual live collector PID probe, and offline adapter verification. Response cooldowns are saved under the shared host lock before release; redirect deadlines apply before destination robots or pages. Shared storage contains only locks and scheduling state; research responses remain in this worktree. The exact loaded robots-retry revision and seven dependencies are independently pinned. The local adapter makes an explicit robots access challenge take precedence over a404/410 classification, preserving the original cache, HTTP status and observation time. `CURRENT-COLLECTOR-ADAPTER-REVIEW.md` records that upstream defect, this adapter’s tested compensation and the separate bounded-retry limitation; the collector source remains read-only.

```sh
python3 scripts/local_lab_summaries.py prepare --append-reviewed
python3 scripts/local_lab_summaries.py validate
python3 -m unittest discover -s tests -p 'test_local_lab_summaries.py' -v
```
